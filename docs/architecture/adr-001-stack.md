# ADR-001: Go для backend, TypeScript для Web

Дата: 15.10.2026. Статус: техническое решение реализовано в каркасе; командное принятие ожидается. ID24_API-22.

## Сравнение

| Вариант | SSE / память | Разработка и эксплуатация | Компетенции команды |
|---|---|---|---|
| Go | Проверены 1000 потоков; context и явное управление жизненным циклом | Один бинарник, типизированные контракты; больше явного кода | Нужен пробный onboarding, не оценивались опросом |
| Node.js + TS | Проверены 1000 потоков; более высокий RSS в данном опыте | Общий язык с Web, event loop требует защиты от CPU блокировок | Нужен такой же onboarding |
| Bun + TS | Не измерялся; нельзя приравнивать к Node | Дополнительная матрица совместимости инструментов | Не подтверждены |
| Python / FastAPI | Не измерялся; имеющийся Python ledger не HTTP benchmark | Быстрое прототипирование, нужен контроль worker/process модели | В репозитории уже есть Python код, этого недостаточно для оценки всей команды |

Выбран Go для gateway/api/worker, Next.js + React + TypeScript для ЛК. PostgreSQL, Redis, ClickHouse, JetStream и S3 по ADR-002. Текущий server использует net/http: chi и pgx выбраны для следующего шага, зависимости не добавляются без использования. Версии целевых библиотек и инструментов: [library-versions.json](library-versions.json); используемые версии фиксируются go.mod/go.sum и pnpm-lock.yaml. TypeScript 5.9.3 выбран из-за compiler API генератора; TypeScript 7 оказался несовместим с openapi-typescript и typescript-eslint.

## Измерение

Скрипт: `make bench`. Go и Node получают одинаковые 1000 открытых SSE, по 3 прогона, соединения создаются пакетами по 25, удерживаются 2 секунды. Проверяются 1000 одновременно активных соединений и ноль после закрытия. RSS снимается через ps, first-event latency меряется клиентом. [Полные исходные результаты и окружение](benchmarks/sse-results.json).

| Реализация | p95 первого события, диапазон трёх прогонов | Дополнительный RSS на поток |
|---|---|---|
| Go | 1.630–2.405 мс | 30.064–30.528 КиБ |
| Node | 2.317–3.410 мс | 42.128–47.056 КиБ |

Это loopback на одном Mac, без TLS, валидации, БД и upstream. Разница мала и не является доказательством production SLO или универсального преимущества языка. Python/Bun не получили выдуманных результатов. Для Beta нужен отдельный тест настоящего gateway с метриками NFR. Решение учитывает простую эксплуатацию Go; общая TS модель сохраняется через генерацию SDK.

Последствия: два языка в toolchain, необходим контрактный CI; Go adapters не должны хранить HTTP-контекст после отмены. Альтернатива Node остаётся разумной при подтверждённом выигрыше команды по скорости разработки. Пересмотр при устойчивом провале NFR или невозможности onboarding.
